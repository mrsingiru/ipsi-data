# ipsi-data — AI 입시 컨설턴트 공개 자료 저장소

나이스 교육정보 개방 포털의 공개 자료를 매일 오전 4시 30분(한국 시간, GitHub 예약이라 20~30분 늦게 시작하기도 함)에 받아 `data/` 폴더에 저장합니다. 사람 손 없이 GitHub Actions가 돕니다.

| 파일 | 내용 |
|---|---|
| `data/schools.json` | 시·도 구·군별 초·중·고 학교 목록(학교 이름 고르기용) |
| `data/schools.csv` | 같은 목록을 표로(학교 코드·고교 유형·주소 포함) |
| `data/changes.md` | 새로 생긴 학교·없어진 학교·이름이 바뀐 학교 기록 |
| `data/exams.json` | 중·고등학교의 중간·기말·지필평가 날짜(학교가 나이스 학사일정에 올린 것) |
| `data/exam_names.md` | 시험으로 본 행사 이름과 뺀 이름(거르는 규칙 점검용) |
| `data/run.json`, `data/exams_run.json` | 마지막 실행 결과 |
| `data/status.json` | 마지막 실행의 성공·실패, 시작·끝 시각, 실행 기록 주소(성공·실패 모두 남김). 자료 점검 예약이 이 파일로 운영실 '자료 수집기' 상태를 고친다 |

## 공식 공고 읽기(매일 오전 5시 40분)

영재원·학교·교육청 누리집의 모집 공고에서 **날짜가 든 줄만** 뽑아 `data/official/<기관 id>.json`에 둡니다. 페이지 자료 점검(매일 06:16)이 이 결과를 원문 근거로 써서, 대표가 손으로 확인할 일을 줄입니다.

| 파일 | 내용 |
|---|---|
| `watch/targets.json` | 읽을 곳 목록(기관 id·누리집·공지 목록·공고 글·GED 공고 목록에서 찾을 이름) |
| `data/official/<id>.json` | 연 주소와 결과, 찾은 공고 제목, 첨부(PDF·HWP·HWPX) 기록, 날짜가 든 줄(160자 안) |
| `data/official_run.json` | 마지막 실행 요약(날짜 줄을 찾은 대상 수) |

- robots.txt를 먼저 읽고 막힌 곳은 열지 않습니다. 우회하지 않습니다.
- 사이트마다 1초 넘게 쉬고, 한 번 실행에 사이트당 15번까지만 엽니다. 이름(User-Agent)을 밝힙니다.
- 로그인 페이지, 제목에 '명단'·'합격자'가 든 글·파일은 열지 않습니다.
- 원문 전체는 저장하지 않고, 날짜가 든 짧은 줄과 주소만 남깁니다.
- 그림으로만 된 일정표는 아직 읽지 못합니다.
- GED(한국교육개발원) 공고 목록 자동 읽기는 멈춰 두었습니다(2026-10-21). KEDI 정책에 '서면 동의 없는 DB 구축·영리 이용 금지'가 있어 서면 확인 전까지는 각 교육청·대학의 원 공고만 읽습니다. `watch/targets.json`의 `"ged": true`로 다시 켭니다.

## 출처 점검(매주 월요일 오전 5시 10분)

페이지가 근거로 쓰는 주소 목록(`watch/sources.json`, 431곳 — ipsi-site의 `tools/build_sources.py`가 판을 낼 때마다 만듦)을 열어
**링크가 살아 있는지, 내용이 바뀌었는지**만 봅니다. 공식 원문(날짜가 걸린 곳)은 매주, 기사·학습 사이트는 4주마다 엽니다.

| 파일 | 내용 |
|---|---|
| `watch/sources.json` | 주소·이름·종류(공식/기사)·분류·쓰는 항목 id·확인 주기 |
| `data/sources_status.json` | 주소마다 마지막 확인 시각·상태·내용 지문(해시)·바뀐 시각·연속 실패 수 |
| `data/sources_report.md` | 끊김(두 번 연속 못 엶)·바뀜(이번 주 내용이 바뀐 공식 원문)·옮김 목록 |

- 원문은 저장하지 않고 상태·지문·제목만 남깁니다. robots·로그인·명단 규칙은 위와 같습니다.
- 언론 기사(일부 매체가 'AI 학습·이용 금지'를 표시)와 GED는 자동으로 열지 않습니다(이용 조건, 2026-10-21).
- 조회수·광고처럼 늘 바뀌는 곳은 세 번 연속 바뀌면 '늘 바뀜'으로 두고 알리지 않습니다.
- 자료 점검 예약(매일 06:16)이 이 결과로 운영실에 '출처 바꾸기·확인 필요로 내리기' 제안을 만듭니다.

## 규정 점검(매주 일요일 오전 5시 20분)

우리가 지켜야 하는 플랫폼 정책·법·자료 이용 조건·도구 약관을 모은 **규정 대장**(`watch/rules.json`, 사람이 고침)의 원문을 열어
**바뀐 부분이 있는지**만 봅니다. 결과는 마케팅 주간 예약(일요일 14:42)이 읽고, 우리 영향을 판단해 입시 운영실에 올립니다.

| 파일 | 내용 |
|---|---|
| `watch/rules.json` | 규정(우리 말 요약·우리가 하는 것·연결된 발행 전 점검 항목·바뀌면 할 일)과 원문 주소·감시 낱말·확인 방식(auto·ai·manual)·주기 |
| `data/rules_status.json` | 원문마다 마지막 확인 시각·상태·부분(제목)별 지문·페이지가 밝힌 수정일·감시 낱말 개수·바뀐 부분 |
| `data/rules_report.md` | 높음(감시 낱말이 사라짐, 수정일과 내용이 함께 바뀜)·보통(바뀐 부분)·낮음(처음 기록·못 읽음) 목록과 관련 규정 |

- 원문 전체는 저장하지 않고 제목(80자 안)·지문·수정일·낱말 개수만 남깁니다. robots를 지키고, 막힌 곳은 '직접 확인'으로 다룹니다.
- 본문이 자바스크립트로만 보여 글이 거의 없는 페이지는 '못 읽음'으로 표시하고, 마케팅 주간 예약이 원문을 직접 엽니다.
- 법·자료 이용 조건·음성 도구 약관처럼 자동으로 열기 어려운 것(`method` `ai`·`manual`)은 여기서 열지 않습니다. 마케팅 주간 예약이 차례(확인일 + 주기)를 보고 공식 사이트에서 확인하거나 대표 확인을 만듭니다.
- 새 규정을 더할 때는 `rules`에 규정을, `sources`에 원문 주소와 감시 낱말(우리가 기대는 사실을 나타내는 짧은 말)을 넣습니다. 처음 실행에서 페이지에 없는 감시 낱말은 보고서 '처음 기록'에 따로 적힙니다.

## 처음 한 번 설정(대표)

1. 나이스 교육정보 개방 포털에서 인증키를 받습니다.
2. 이 저장소의 **Settings → Secrets and variables → Actions → New repository secret**에서
   이름 `NEIS_KEY`, 값에 인증키를 넣습니다. 인증키는 이 곳 말고는 어디에도(대화창 포함) 붙여 넣지 않습니다.
3. **Actions → 나이스 자료 받기 → Run workflow**에서 mode를 `all`로 한 번 실행합니다(처음엔 시간이 걸립니다).
   그다음부터는 매일 저절로 돕니다.

## 지키는 것

- 공개 자료만 받습니다. 학생 개인 정보는 받지 않습니다.
- 인증키는 GitHub 비밀 값에만 두고, 실행 기록에도 찍지 않습니다.
- 나이스 하루 호출 한도에 걸리면 받은 데까지 저장하고 멈춘 뒤, 다음 날 남은 학교부터 받습니다.
- 학교 수가 지난번보다 10% 넘게 줄면 오류로 보고 저장하지 않습니다.
- 시험 날짜는 학교가 올린 행사 이름으로 거른 것이라 빠지거나 바뀔 수 있습니다. 페이지에는 '학교 학사일정 기준'과 받은 날짜를 함께 표시합니다.
